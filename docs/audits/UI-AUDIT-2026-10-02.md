# UI Audit — Production (`finance.investdx.biz.id`)

**Date:** 2026-10-02
**Scope:** every route in `apps/web/app` — `/`, `/login`, `/invite`, `/inbox` (+ aliases `/reviews`, `/actions`), `/transactions`, `/analytics`, `/wealth`, `/documents`, `/household`, `/settings`, `/admin`, `/privacy`, `/terms`.
**Account:** signed in as the workspace owner (Super admin), data as of 2 Oct 2026.

## How it was tested (read this before trusting a result)

| Target | Method | Confidence |
|---|---|---|
| Web (desktop) | Real Chrome, ~1400–1920px wide | High |
| Tablet | Real Chrome window at 768px | High. The app uses its phone layout (bottom tab bar) at this width. |
| Phone | Chrome window at 500px (its minimum), then **CSS-zoom emulation** of 375px and 393px with width media queries rewritten to match | Medium. Tests layout, wrapping and overflow only. Not real Safari, no touch, no safe-area or address-bar behaviour. |
| Public pages on phone/tablet | Built-in browser pane with true 375×812 / 768×1024 emulation | High |

Target devices named by the owner: **iPhone 14 Pro Max (430px)** and **iPhone 15 (393px)**.
**Not tested:** 430px, landscape, real Safari, the "Lainnya" menu contents, keyboard focus order and focus styles, state-changing flows (add transaction, upload, deactivate member), `/inbox` with real items (it was empty).

Findings that were wrong in earlier notes and are **dropped**: `/inbox` and `/actions` are intentional aliases (`/reviews` redirects to `/inbox?view=transactions`); signed-out `/login` is a proper page (the blank screen was the signed-in redirect state); the "tiled" `/invite` card was a screenshot artifact.

## Phone (375 / 393 / 430px)

| ID | Sev | Issue | Where | Suggested fix |
|---|---|---|---|---|
| P1 | ~~High~~ Withdrawn | **Not a confirmed bug.** On `/analytics` the comparison ledger is an intentional horizontal scroller (sticky label column, scroll-snap, edge shadows that appear only while it overflows; see `06-analytics-and-cycle-review.css`). In the 393px CSS-zoom emulation only one cycle column was visible, but column widths use container units (`cqw`), which the emulation likely skews. Needs a check on a real iPhone before treating it as an issue. | `/analytics` | Verify on device; no change made. |
| P2 | Med | At 375px, "Rp 16.317.359" breaks as "Rp 16.317.35 / 9". Fine at 393px; larger amounts (over ~99 juta) will wrap there too. | `/` KPI tiles | `white-space: nowrap` and fluid font-size; verify at 360px and 430px. |
| P3 | Low (verify) | Tab row is clipped: three secondary buttons sit past the right edge. Probably an intentional scroll row; confirm there is an edge cue on a real device. | `/admin` | Add a fade or edge shadow, or wrap the tabs. |
| P4 | Med | `/wealth` overflows sideways by 4px at 500px. A `<small>` inside `.wealth-history-row` buttons runs past the page edge. | `/wealth` | `min-width: 0` and wrapping on the row's text. |
| P5 | Med | `/settings` and `/documents` are about 8,300px and 8,500px tall. The anchor links are tiny wrap-around text. | `/settings`, `/documents` | Collapsible sections or a sticky section picker; paginate documents. |
| P6 | Low | `viewport-fit=cover` is not set, so the bottom nav's `env(safe-area-inset-bottom)` padding does nothing if the site is added to the iOS Home Screen. | Root layout | Export a `viewport` with `viewportFit: "cover"`. |
| P7 | Low | On `/login` the form card starts below the fold on a 375px phone. | `/login` | Tighten the hero or move the form up. |

Phone items that **work**: bottom tab bar fits five items with readable labels; cards stack cleanly; Transaksi filters collapse to one column; inputs are 16px so iOS will not zoom the page when focusing a field; pinch-zoom is allowed.

## Suggested fix order

1. **X1, X2, X3**: labels, type floor, hit areas. These are mostly CSS plus a few attributes and apply everywhere.
2. **P2**: amounts wrapping on narrow phones. (P1 was withdrawn after review; verify the analytics ledger on a real iPhone.)
3. **X4, X5**: loading and chart sizing; these affect first impressions of the dashboard.
4. **P3–P6, T1, W1, W2**: layout polish.
5. **Low**: copy and label cleanup (X6–X9, W3, W4, P7, T2).

Retest on a real iPhone 14 Pro Max and iPhone 15 in Safari after fixes, focusing on `/analytics` and the dashboard.
